# 调价后油枪示值复核与短溢回执台

- 行业：石油
- 技术栈：Vue3、Vite、TypeScript、Pinia
- 启动：`npm install && npm run dev`
- 构建：`npm run build`

在“油品价格维护”基础上扩展为调价后油枪示值复核与短溢回执台。数据默认保存在浏览器 localStorage 中，方便后续替换为接口实现。

## 业务闭环

1. **批次下发**：登记操作员、拟生效日期、新挂牌价，并按油枪登记核验项（枪号、班组、示值、计量罐读数、检定期），系统按枪项生成待回填的短溢回执，批次进入“待复核”。
2. **登记约束**：同枪同班在一个批次内只能一条，重复录入在登记前拒收并保留全部已输入内容。
3. **整批阻断**：检定期已过，或示值相对偏差 `|示值-计量罐读数|/计量罐读数` 超过千分之三（3‰），整批停在待复核，输入保留。
4. **回执回收**：班组逐枪回填补差量（正溢/负短/平）、责任类型和说明；未收回全部回执前新挂牌价不得启用，原价继续生效。
5. **核验冻结**：无阻断冲突且回执全部收回后方可核验；核验完成后批次、枪项、回执全部冻结不可改。
6. **更正版本**：对已冻结批次的更正只能“另建带原因版本”，版本号 +1，重新走待复核流程。
7. **刷新一致**：所有判定基于持久化数据实时重算，刷新后批次、枪项、回执与版本对应关系不变；冲突清单统一列出批次、枪号、偏差与命中规则。

## 分层结构（数据、判定、存储、页面分开）

- `src/verification/types.ts`：数据模型与常量（数据层）
- `src/verification/seed.ts`：首次进入的演示数据（数据层）
- `src/verification/rules.ts`：偏差、检定期、同枪同班、回执完整性等判定，全部为纯函数（判定层）
- `src/verification/storage.ts`：localStorage 读写与存档结构自检（存储层，可整体替换为接口）
- `src/verification/store.ts`：Pinia 编排，串联数据/判定/存储并实施冻结保护（编排层）
- `src/components/`、`src/App.vue`：页面与交互（页面层）

未增加任何新依赖。
